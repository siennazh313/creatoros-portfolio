# CreatorOS v2 接入、数据口径与验证

## 架构和接口

沿用 Python 标准库 HTTP + SQLite，前端为本地原生 ES modules，无CDN或字体下载。`workspace.py`负责迁移、分析与导入；`sync.py`负责三平台Dataset适配与日志。前端按API、工具、图表、表格和页面拆分。

GET `/api/meta` 返回数据截止日、国家、平台、导入字段契约和同步状态。
GET `/api/dashboard`、`/api/countries`、`/api/commerce` 返回同一筛选工作集中的大盘、国家、创作者和转化汇总。国家/创作者内仅返回商业汇总，明细在顶层commerce中。
GET `/api/contents` 返回内容；加content_id返回该条内容的趋势、词云、主题和评论样本。
GET `/api/discoveries` 返回未合作候选达人、推荐证据、联系历史和权重。

共同查询参数：`start=YYYY-MM-DD`、`end=YYYY-MM-DD`、`grain=day|week|month`、`platform`、`country`；dashboard/contents支持creator_id，contents另支持content_id。省略日期以账号指标、内容快照、加热与转化中的最近日期向前30天，最多731天。国家和商业接口为统一工作集别名，浏览器负责不同视图。

POST `/api/records/import`：`{"kind":"snapshots","records":[...]}`，支持profiles、accounts、contents、snapshots、comments、candidates、campaigns、heating、conversions。完整字段、必填字段以meta.contracts为准；数据管理可下载模板。缺失数值用null或CSV空格（不填内容），不要填写字符串“—”。
POST `/api/candidate-update`：id、favorite、owner、status、promote。联系人状态为待评估/待联系/已联系/洽谈中/暂缓。转入试合作需负责人，建立账号和档案，候选记录及历史继续保留。
POST `/api/weights`：weights对象，键为growth/engagement/stability/fit/coverage；非负、总和大于0。
POST `/api/sync`：读取所有已配置平台的现有Dataset；缺少配置返回错误，不标成功。

兼容原state、health、diagnose、creator-update、tasks、task-update、import、collect、export接口。旧诊断接口保留原后端兼容能力，正式页面不呈现其实现细节。

## 导入示例

先导入档案，再平台账号，接着内容/活动，最后快照、评论、加热及转化。账号日指标仍通过旧import CSV接口导入，数据管理页面同时支持JSON文件转换。

```json
{"kind":"profiles","records":[{"id":"P100","name":"Aya Mori","platform":"Instagram","country":"JP","tier":"B","status":"试合作","owner":"Sienna","topic":"生活方式"}]}
```

```json
{"kind":"accounts","records":[{"creator_id":"P100","platform":"Instagram","handle":"aya_example","url":"https://www.instagram.com/aya_example"}]}
```

内容档案字段：id、creator_id、published_at（ISO日期或时间）、kind（视频/图文/文字）、title、url。
内容快照：content_id、date、views、likes、comments、shares、saves、organic_views、paid_views，均为截至date的累计值；不可回退。自然与付费均有值时其和必须等于views。
评论：id、content_id、date、text、topic；未提供topic归入其他。当前词云采用英文词元和连续中文文本片段，不包含复杂中文语义分词；主题来自导入标签，未接入自动情感分类。

```json
{"kind":"campaigns","records":[{"id":"launch-jp","creator_id":"P100","tracking_code":"aya-jp","invite_code":"AYAJP"}]}
```

加热字段：id、date、creator_id、content_id、campaign_id、currency、spend、impressions、paid_views、clicks、visits、registrations。单条代表某活动/内容/日期的聚合记录，费用和访问等字段按幂等主键更新；不要同时导入重叠统计范围的两组记录。

```json
{"kind":"conversions","records":[{"id":"registration-1","date":"2026-11-10","kind":"new_user","user_id":"user-1","invite_code":"AYAJP","currency":"JPY"},{"id":"payment-1","date":"2026-11-10","kind":"order","user_id":"user-1","order_id":"order-1","tracking_url":"https://example.com/?tracking_code=aya-jp","amount":6800,"refund":0,"currency":"JPY","status":"paid"}]}
```

转化关联支持creator_id、campaign_id、tracking_code、invite_code或tracking_url的同名查询参数。多种标识一致才关联；冲突或标识不存在进入conflict，无标识进入unattributed。不按播放量分摊。用户事件以user_id、订单以order_id全局去重；重复导入更新同一记录。退款更新原订单的refund；pending、cancelled订单不计入GMV。

## 统计口径

- 国家变化贡献为本期减前期的绝对播放/浏览变化，汇总与大盘严格一致；缺口国家标记，只反映已观测变化。总体结论可分析数据完整的账号子集，但不对缺失账号下确定性判断。
- 互动率以互动总量/播放浏览总量加权；单篇播放为周期播放/发布篇数，含历史内容播放，属于账号经营效率指标。
- 日指标为当日新增值，内容快照为累计值，两者不相加。期间内容指标以截止日最近快照减开始日前最近快照；历史内容缺少起始快照时显示缺失。快照非逐日时增量落在观测日，仅说明观测期间变化，不能证明日内分布。
- 自然周从周一开始，自然月从1日开始；选区边界截断的周期标记未完整覆盖。缺少全部观测的日期断线；总体内部分账号缺失由完整性提示说明。
- 原异常仍固定近7日对前7日，阈值25%；采集缺口优先，低样本不直接诊断经营异常。付费变化参考同一7日窗口加热表的付费播放；没有记录时不判断。
- 支付GMV是成功支付订单金额，净GMV扣除退款；投放回报为净GMV/费用。点击率=点击/付费曝光；访问注册率=注册/访问；访问购买率=去重购买用户/访问；新客获取成本=费用/新增用户。它们是关联活动经营效率，包含自然来源时不宣称付费增量因果效果。
- 漏斗为活动阶段汇总，并非同一访客队列；首次付费用户以已导入全量支付历史的首次日期判断。历史不全会影响首次判断，需要上游提供完整历史。漏斗条宽按访问占比绘制。
- 金额按币种分别计算，不换算、不跨币种求和；总体新增用户跨币种去重，币种局部人数不应再相加。没有访问会话标识，访问与注册采用来源聚合口径，新增用户、购买用户和订单按独立标识去重。
- 达人增长、互动分别按30%、8%归一上限，稳定与领域匹配按0—1输入；权重默认25/25/20/15/15。得分≥65优先联系、≥45持续观察，否则暂缓。缺关键指标待评估。国家覆盖以签约中/试合作名单计算；未知国家不作为新市场机会。

## 上游和调度

`.env`在启动和计划任务中自动加载，现有环境变量优先。分别配置TIKTOK_DATASET_ID、THREADS_DATASET_ID、INSTAGRAM_DATASET_ID及APIFY_TOKEN；对应FIELD_MAP以“上游键→内部键”映射。Dataset行用record_type指定上述类型，账号日指标使用metrics，省略record_type默认候选达人。

每天08:00（北京时间）的Windows任务由schedule.ps1安装，失败5分钟后重试，最多3次，重复实例忽略。未安装前不会自动运行；平台在线爬取由上游服务负责。本轮提供接入适配，未使用任何真实凭据进行联网联调。

## 验证范围

自动测试覆盖历史任务反馈保留、迁移幂等、国家贡献、加权指标、自然周期边界、快照差分与回退拦截、导入原子性、订单/用户去重、退款和多币种、标识冲突、邀请码、候选去重与转入、同步失败和重试。

浏览器人工验证覆盖首页、国家→创作者→内容下钻、词云与主题、达人推荐、漏斗、表格搜索/排序/分页、数据管理、无配置同步错误、响应式布局。未来上线真实来源后，还需核对各平台字段授权、累计指标定义、订单状态与时区。

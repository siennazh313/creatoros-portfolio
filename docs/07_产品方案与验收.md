# CreatorOS：经营分析到可验证决策

## 产品定位与用户

面向海外创作者运营与增长团队，解决“发现大盘变化后，无法快速确定国家、平台、创作者、内容与转化环节的重点核查对象”的问题。产品目标是缩短从发现信号到形成可验证动作的路径，不声称已测量实际节省工时或经营提升。

## 信息架构

经营总览发现变化；国家分析解释市场贡献；创作者与内容定位具体对象；分析工作台聚合证据、生成原因假设和验证动作；达人发现补充供给；加热与转化连接直接归因的经营结果；运营任务承接执行和反馈；数据管理控制输入质量。各模块共享日期、平台和国家筛选。

## 分析工作台

1. 完整性检查：等长周期、样本数量、缺失账号日，先补数再归因。
2. 多维定位：国家与平台绝对增减贡献可回加到大盘；指标比率采用加权口径。
3. 创作者分解：用对称分解计算发布量变化与单篇播放变化的贡献，两项之和等于播放变化；属于恒等式分解，不是因果证明。
4. 内容与商业核查：读取评论抽样、主题与直接归因的用户/订单结果；展示缺失或选择偏差。
5. 策略：形成重点建联、选题与发布核查、补数等行动；每项明确证据、负责人和验收标准。
6. 复盘：采纳为任务，记录执行与拒绝原因，再回到创作者页面观察后续指标。前后变化不能单独证明策略有效。

## 模型与规则的职责

证据分析由确定性代码完成指标计算和异常筛选。模型分析通过Responses API有界工具循环运行：模型必须读取总体和维度证据，随后自主选择创作者、内容和转化工具，最后返回结构化诊断。模型不执行任意SQL、外部链接访问、发消息或投放。

服务端校验输出、证据引用、创作者标识及行动验收标准；未完成输出、未知工具或无依据引用均报错，不转换为成功。单次最多6轮、每轮2500输出tokens。访问码仅在服务端配置，密钥不进入网页或GitHub。

## 当前真实状态

公开网页可实际演示筛选、下钻、评论分析、浏览器内日指标CSV/JSON导入、证据工作台和任务闭环。公开数据独立生成，真实业务数据未公开。

已创建API密钥并通过GET /v1/models鉴权检查。真实Responses分析请求返回HTTP429 credit_balance_exhausted；当前尚无成功的真实模型诊断验收记录。用户已选择暂不充值，因此不将模拟上游测试计为真实模型成功。模型服务部署与功能测试记录分别保留，待补充额度和云端密钥后再验收真实调用。

云端后端与Python本地后端均提供模型工具调用实现。公开页面保留既有GitHub Pages链接，通过独立服务接入模型。云端服务在未配置密钥/访问码时明确返回503，不产生模型调用。云端按来源的频率控制为实例内保护，不承诺全局费用上限；启用前应设置项目预算及调用管理。
